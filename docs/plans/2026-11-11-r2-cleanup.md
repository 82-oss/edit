# R2: what can go, and how to delete it safely

Sphe, Nov 11: "lets not delete yet, have an md so we can delete in the future". Nothing below has been deleted. The numbers are a read-only audit of prod on Nov 11 2026 (`app/scripts/r2-audit/`, steps below); run it again before acting, since the bucket grew by about 50 GB a day. What stops it growing (old review versions retired on share, a shared export kept once, Edit's cleanup queue emptied by the relay, cloud-sweep.ts counting Writer's footage) is built and on prod since Nov 14.

## The bucket

The prod bucket `foia-render-results` (dev's is `edit-dev`) held 1,659 GB, about $25 a month, all storage: `edit/` 1,122 GB, Repack's `repack/` and `projects/` 444 GB, `writer/` 92 GB.

## What can go, on Sphe's go

- **Repack's and Writer's prefixes (536 GB).** Sphe: "i dont think we use these sites anymore". Confirm first that nothing Edit uses still reads them: 83.7 GB of `edit/originals/` is held only by live Writer scripts (their `edit-shared.json`).
- **Orphans (58 GB, nothing uses them, last written 14+ days ago):** sped-up or cut originals from Oct 20–21 (`edit/originals/sha256/…-1.5x-<hash>.mp4`, 27.8 GB), benchmark files under `edit/test/` (13.8 GB), `edit/exports/results/` (5.35 GB), `edit/reviews/tmp/` (1.8 GB), old Drive originals (4.75 GB). Review files of three deleted projects (`p1793192147016-15`, `p1793187023555-2774`, `p1793391913951-3011`, 2.8 GB) still have open links: close those reviews first.
- **Superseded review versions (239 GB).** Each project's older versions now go when it's shared again; reviews never shared again keep theirs. Keep each project's latest version (its link plays), close a review before deleting its files.
- **A lifecycle rule on the temporary prefixes** (`edit/test/`, `edit/exports/results/`, `edit/reviews/tmp/`, `edit/transcribe/`, `edit/proxies/jobs/`): delete objects older than 7 days (`npx wrangler r2 bucket lifecycle add foia-render-results …` once per prefix). Adding it deletes what's there, so it waits for the go too.

Done projects' footage is the footage sweep's (below), not a hand deletion.

## How to delete

1. Run the audit again: never act on these numbers or an old key list.
2. Footage (originals, proxies, pieces, excerpts): delete the files, mark their `editMedia` rows not ready, record what was freed so it can be restored. Deleting an original without its registry row means the next import of that Drive or YouTube file reuses a key that's gone.
3. Originals from someone's disk (`edit/originals/sha256/…`) can't be fetched again; Drive and YouTube originals can. Exports read originals, so re-exporting a project whose originals went downloads them first.

## Running the audit

Read-only throughout (LIST on R2, `convex data` and the read-only `edit:getProject` on Convex). From a folder `D`:

1. R2 listing: the R2_* secrets from infisical (`--env=prod --path=/edit-relay`) in the environment, `bun app/scripts/r2-audit/list.ts D/r2.tsv`.
2. Convex dumps into `D/cx/<table>.jsonl` (editProjects, editLater, editLocks, editMedia, editNotes, reviews, reviewVersions, writerScripts, ideas, thumbnails, thumbnailAssets, projectSizes, cleanup): `cd ~/Documents/code/accounts && infisical run --env=prod --path=/mamagi -- bunx convex data <table> --limit 50000 --format jsonLines > D/cx/<table>.jsonl` (analyze.py reads editMedia from `editMedia.16000.jsonl`).
3. Project bodies: `bun app/scripts/r2-audit/bodies.ts D` (CONVEX_URL and CONVEX_SERVICE_TOKEN from the same infisical path).
4. `python3 app/scripts/r2-audit/analyze.py D`, then `python3 app/scripts/r2-audit/report.py D`: the tiers, the CSVs and the key lists.

## The footage sweep (built Nov 15, off)

Sphe, Nov 15: "done projects which have been inactive/not even opened for 30 days get their footage deleted". mamagi's `convex/footage.ts` (rules in `footagePlan.ts`) runs daily from the relay at 03:15 UTC: a project Done on Home and untouched 30 days has the footage only it uses queued for deletion, its registry rows marked not ready and `footageCleared` set; opening it in Edit offers Bring the footage back (FootageBack). A live Writer script holds its footage until it has been made into an edit and is itself untouched 30 days. Finished projects sharing a source clear it together. It ships as a dry run (`SWEEP.clear` false). Read what it would do with `bun scripts/footage-report.ts [--all] [--ahead <days>]` in accounts, under `infisical run --projectId=979fe56c-c4d0-4809-b64f-5ebc75eeaf05 --env=prod --path=/edit-relay --silent --`.

Nov 15 dry run: nothing on prod is 30 days past its last touch yet. 30 days on with nothing touched, 50 projects would clear 205.0 GB (188.6 GB fetchable again, 16.3 GB from someone's disk, 16.2 GB of it one file of "Predator Teacher…").

To turn it on: a nightly with FootageBack on the team's Macs (nightly-74 doesn't have it), mamagi deployed with accounts f30e3ba (shared sources cleared together; its commit says not deployed), then `SWEEP.clear = true` and deploy mamagi again, around Dec 15.
